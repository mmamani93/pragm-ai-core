# Security and privacy policy

## Reporting a vulnerability

Do not include customer prompts, responses, credentials, transcripts, file names, paths, URLs, production telemetry, or other personal or confidential information in a public issue.

Report a suspected privacy or security problem through GitHub's private vulnerability-reporting flow for this repository. If that flow is unavailable, contact the maintainer through a private channel listed on the maintainer's GitHub profile. Provide only the minimum reproducible synthetic example, the affected version, the impact, and safe reproduction steps. Do not test against another person's installation, customer data, or production systems without prior written authorization.

## Supported versions

Security fixes are provided only in the latest published release unless a release notice explicitly says otherwise. Older releases remain available for reproducibility but are not maintained. Users are responsible for monitoring release notices, deciding whether an update is appropriate, verifying its signature and SHA-256 digest, obtaining any required authorization, backing up affected configuration, testing compatibility, and applying the update.

An update check is informational and does not install software. No response time, remediation time, maintenance, support, or notification commitment exists unless agreed separately in writing. See [LICENSE](LICENSE) for the warranty, liability, and user-responsibility terms.

## Verification and disclosure

Verify the release signature and SHA-256 digest before executing a downloaded artifact. Stop if verification fails. Allow reasonable time for investigation and a safe release before public disclosure; coordinated disclosure does not authorize access to systems or data.
